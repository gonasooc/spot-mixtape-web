# 제품 기획

무엇을 누구를 위해 만드는지와 제품의 범위·정책을 다룹니다. 개별 작업의 구현 순서와 진행 상황은 `docs/work/`의 작업 문서에서 관리합니다.

브랜드 톤과 안티레퍼런스의 원본은 [PRODUCT.md](../PRODUCT.md)입니다. 이 문서는 그 내용을 범위·정책 관점으로 정리하며, 톤 관련 판단이 필요하면 원본을 함께 읽습니다.

## 목적과 사용자

[spotMixtape](https://github.com/gonasooc/spot-mixtape) 앱(iOS·Android 개인 사운드 아카이브)의 공개 웹 표면입니다. 앱이 무엇인지 한 번에 전달하는 랜딩 하나와, 스토어 심사·국내 법령이 요구하는 개인정보처리방침·이용약관을 제공합니다.

- 앱 링크로 유입된 잠재 사용자. 장소의 순간을 사진만이 아니라 소리로 남기고 싶은 사람.
- 스토어 심사관과 법률 문서를 확인하러 온 이용자. 장식 없이 빠르게 읽어야 합니다.

## 이번 범위

- 제공할 것: 랜딩(`/`), 개인정보처리방침(`/privacy`), 이용약관(`/terms`), 계정 삭제 안내(`/account-deletion` — 방침의 해당 장으로 보내는 리다이렉트 스텁), 404.
- 이번에는 다루지 않을 것: 아래 ‘다루지 않기로 한 것’ 참고.
- 성공을 확인하는 기준: 로그아웃·JavaScript 비활성 상태에서도 네 페이지의 전문을 읽을 수 있고, 스토어 콘솔에 등록한 URL이 모두 200을 반환합니다.

### 다루지 않기로 한 것

의도적으로 만들지 않은 것들입니다. 나중에 "빠졌다"고 오해하지 않도록 남깁니다.

| 항목 | 이유 |
| --- | --- |
| 웹 애널리틱스 | 앱과 동일하게 분석 SDK를 넣지 않는다는 제품 원칙을 따릅니다. 넣으려면 개인정보처리방침의 위탁·쿠키 항목을 함께 고쳐야 합니다 |
| 다국어(i18n) | 현재 한국어 단일 언어입니다. 글로벌 스토어 심사용 영문이 필요하면 앱 저장소의 `legal-site/` 영문본을 쓰거나 이 사이트에 라우트를 추가합니다 |
| 문의 폼 | 폼 제출은 서버가 필요하고 CSP `form-action 'none'`과 충돌합니다. mailto 링크로 대체했습니다 |
| 다크·라이트 테마 토글 | 앱이 다크 테마 기준이므로 사이트도 고정했습니다. [docs/design.md](design.md) 참고 |
| 블로그·변경 이력 페이지 | 요청 범위 밖 |

## 핵심 기능과 사용자 흐름

- 랜딩은 4개 섹션입니다: 히어로 → 핵심 루프(기록·보관·공유) → 운영 원칙 → 문의 CTA. 앱 화면(Play 스토어 스크린샷에서 잘라낸 다섯 장)은 히어로 카드와 루프 카드의 커버로 들어갑니다.
- 전환 목표는 하나입니다. 스토어 출시 전에는 출시 소식 구독(mailto), 출시 후에는 스토어 버튼. `site.appStoreUrl`과 `site.playStoreUrl`이 모두 `null`인 동안 "출시 준비 중" 상태 표시와 mailto 버튼이 나오고, 한쪽만 채우면 해당 스토어 버튼만 노출됩니다.
- 법률 문서는 제목·시행일·목차·본문만 있는 단일 컬럼 문서입니다. 히어로나 마케팅 문구를 두지 않습니다.
- 계정 삭제는 별도 페이지가 아니라 개인정보처리방침의 한 장이며, 앱과 스토어가 가진 `/account-deletion` URL은 meta refresh로 그 장에 도착합니다.

## 제품 정책과 제약

- **사실만 말합니다.** 랜딩의 모든 주장은 앱 코드베이스와 일치해야 합니다(10초 제한, 비공개 스토리지, 삭제 범위 등).
- **분석 SDK와 광고를 넣지 않습니다.** 폰트도 self-host해 외부 요청이 없습니다. 이 결정을 뒤집으면 개인정보처리방침의 위탁·쿠키 항목을 함께 고쳐야 합니다.
- **정적 우선.** JavaScript 없이도 전문이 읽히는 프리렌더를 깨뜨리지 않습니다.
- **법률 값의 단일 출처는 `src/config/site.ts`입니다.** 문서 본문에 값을 직접 쓰지 않습니다.
- **플레이스홀더가 남아 있으면 색인되지 않습니다.** `src/routes.ts`가 `findUnresolvedConfigKeys()`를 보고 전 페이지를 `noindex`로 돌리고 `robots.txt`를 `Disallow: /`로 씁니다. 값이 모두 채워지면 스스로 색인을 다시 켭니다.
- **변호사 검토는 생략하기로 결정했습니다.** 앱 저장소 `docs/RELEASE_RUNBOOK.md` 2.1에 2026-09-05 OWNER 결정으로 기록돼 있습니다. 이미 검토된 문안을 바탕으로 무료 앱에 맞게 불필요한 조항을 걷어낸 형태로 확정했습니다. 검토를 받게 될 경우의 출발점은 아래 ‘법률 문서의 알려진 보완 후보’입니다.
- **저장소 이름을 바꾸면 공개 URL이 전부 깨집니다.** GitHub Pages project page 경로가 `site.publicOrigin`에 들어 있습니다. 스토어와 방침에 제출한 뒤에는 이름을 바꾸지 않습니다.

## 법률 문서의 알려진 보완 후보

변호사 검토를 생략하기로 한 결정 이전에 정리한 목록입니다. 현재 방침은 앱 저장소의 글로벌 스토어 심사용 영문본을 한국어로 옮긴 것이라, **대한민국 개인정보 보호법 제30조와 시행령 제31조 기준으로는 아래 항목이 빠져 있거나 구체성이 부족할 수 있습니다.** 지금 당장 고치기로 한 것은 없고, 검토를 받거나 방침을 강화할 때 출발점으로 씁니다.

개인정보처리방침:

- **파기 절차와 방법** — 현재는 "삭제 완료 시 제거"만 있습니다. 보유기간 경과·목적 달성 시의 파기 절차와 방법(복구 불가능한 삭제 등)을 별도 항목으로 요구할 수 있습니다.
- **권익침해 구제방법** — 개인정보분쟁조정위원회, 개인정보침해신고센터, 대검찰청, 경찰청 연락처 안내가 국내 방침에는 사실상 표준입니다. 현재 없습니다.
- **국외 이전 세부 고지** — 법 제28조의8은 이전 항목, 이전받는 국가·시기·방법, 이전받는 자의 성명·연락처, 이용 목적·보유기간, 거부 절차·방법의 고지를 요구합니다. 현재는 수탁자와 리전만 밝히고 있습니다.
- **열람청구 접수·처리 부서** — 보호책임자와 별도로 명시가 필요한지 확인이 필요합니다.
- **만 14세 미만 아동** — 앱이 아동 가입을 허용하는지 정하고, 허용하지 않는다면 그 사실과 확인 방법을 기재합니다. 스토어 연령 등급과 일치해야 합니다.
- **자동 수집 장치(쿠키 등)** — 이 사이트와 앱 모두 쿠키·행동 분석 SDK를 쓰지 않습니다. "사용하지 않는다"는 사실을 명시할지 미정입니다.
- **국내대리인 / 가명정보 처리** — 해당 사항이 없으면 기재 불요. 해당 여부만 확인하면 됩니다.

이용약관:

- 타인의 음성·초상 녹음과 공유에 대한 안내 문구(통신비밀보호법, 초상권)
- 위치정보 이용 — 위치정보법상 별도 약관·동의가 필요한지 확인
- 청약철회·환불 조항 — 현재 유료 상품이 없어 불요하나 도입 시 필수
- 준거법·관할 조항이 소비자 강행규정과 충돌하지 않는지 확인

문서를 고칠 때는 `effectiveDate`를 함께 갱신합니다. 장을 추가·삭제할 때 지켜야 할 구조 규칙은 [docs/architecture.md](architecture.md)에 있습니다.

## 아직 결정할 사항

- 보안 응답 헤더를 어떻게 할지. 현재 호스트(GitHub Pages)는 `public/_headers`를 무시하므로 헤더가 하나도 나가지 않습니다. 현 상태 수용 / 다른 호스트로 이전 / 커스텀 도메인 + 프록시 중 선택이 필요합니다. 근거는 [docs/architecture.md](architecture.md)의 알려진 구조 제약, 진행은 [docs/work/W-002-main-security-headers.md](work/W-002-main-security-headers.md)에 있습니다.
- 우편 주소 없이 이메일 연락처만 공개하는 것으로 충분한지. `site.postalAddress`는 현재 `null`이고, 앱 저장소 runbook에서도 미확인 상태입니다.
- 커스텀 도메인을 쓸지. 현재는 `github.io` 하위 경로를 사용합니다. 도메인을 붙이면 `site.publicOrigin` 하나만 바꾸면 되지만, 스토어 콘솔에 제출한 URL도 함께 옮겨야 합니다.
- 린터를 도입할지. ESLint·Prettier가 없습니다. 앱 저장소와 규칙을 맞출지 정해야 합니다.
- PR 시점 CI를 둘지. 현재 워크플로는 main push에만 걸려 있어, 병합 전에 `config:check`·`tokens:check`·빌드가 돌지 않습니다.
- 앱 저장소의 `legal-site/` 디렉터리를 어떻게 할지(제거 / 보관 / 유지). 이 사이트가 정본이므로 두 곳을 모두 두면 문구가 갈라집니다. 앱 저장소 쪽 결정입니다.
- 딥링크를 붙일 계획이 생기면 `public/.well-known/`에 Apple App Site Association이나 Android Asset Links를 추가합니다. 현재는 불필요합니다.

스토어 출시 후에는 `site.appStoreUrl`과 `site.playStoreUrl`을 채웁니다. 스토어 콘솔에 넣을 URL 목록과 그 입력 상태는 앱 저장소의 `docs/RELEASE_RUNBOOK.md`가 관리합니다 — 이 저장소에 중복해서 두지 않습니다.

진행 상황은 [docs/README.md](README.md)의 작업 목록과 각 작업 문서에서 관리합니다.
